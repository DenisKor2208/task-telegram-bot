# Task Telegram Bot

Task Telegram Bot — это многофункциональный бот для управления задачами, написанный на Go. Бот позволяет создавать задачи с дедлайнами, отслеживать их статусы, получать уведомления о приближении дедлайна и управлять личными настройками (например, часовым поясом). Все данные хранятся в PostgreSQL, сессии пользователей — в Redis.

> **❗️ Важно:** Бот находится в стадии тестирования. Возможны изменения и временные неполадки.

## Возможности

- ✅ **Создание задач** с описанием и опциональным дедлайном.
- 📋 **Просмотр задач** с фильтрацией по статусам:
  - В процессе
  - Выполнено
  - Просрочено
  - Завершено
  - Все задачи
- ✏️ **Изменение статуса задачи:** выполнить, завершить, удалить.
- ⏰ **Автоматическая проверка просроченных задач** — задачи, у которых дедлайн истёк, получают статус «Просрочено».
- 🔔 **Уведомления о приближении дедлайна** (настраиваемые интервалы: 3 дня, 1 день, 1 час).
- 🌍 **Выбор часового пояса** пользователя — все даты интерпретируются локально.
- ⚙️ **Просмотр текущих настроек** (часовой пояс).
- 💾 **Хранение сессий в Redis**
- 🗃️ **Миграции базы данных** через встроенную утилиту.
- 🐳 **Готовность к запуску в Docker** (docker-compose).

## 2. Настройка конфигурации

### Настройте переменные окружения

Скопируйте файл с примером переменных и отредактируйте его, указав реальные данные:

```bash
cp .env.example .env
```

Откройте .env и задайте значения:

- TELEGRAM_TOKEN — токен вашего Telegram-бота (получить у [@BotFather](https://t.me/BotFather)).
- Параметры PostgreSQL: `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` (оставьте как есть, если не меняете).

В проекте предусмотрены два конфигурационных файла:

- `config/config.yaml` — для локального запуска приложения
- `config/config.docker.yaml` — для запуска приложения полностью в Docker

Файлы `config/config.yaml` и `config/config.docker.yaml` содержат значения по умолчанию для соответствующих окружений. Переменные из файла `.env` загружаются в окружение (благодаря импорту `_ "github.com/joho/godotenv/autoload"`), а затем библиотека `cleanenv` через вызов `ReadEnv` перезаписывает поля конфигурации, помеченные тегом env. Таким образом, приоритет имеют переменные окружения.

**Важно:** подстановки вида `${VAR}` в `YAML` не обрабатываются; значения должны быть либо явными, либо пустыми (тогда они будут заменены из переменных окружения).

## 3. Для локального запуска

Отредактируйте файл `config/config.yaml`, указав, если нужно, свои значения (токен бота, строку подключения к PostgreSQL, параметры Redis и т.д.).
Файл `config/config.yaml` уже содержит готовые значения для локальной разработки. Если вы хотите их изменить, вы можете либо отредактировать этот файл, либо задать соответствующие переменные окружения в `.env` (например, `DATABASE_URL`, `REDIS_CONNECTION_STRING`,...), которые имеют более высокий приоритет.

### PostgreSQL и Redis через Docker

Если у вас установлены `Docker` и `Docker Compose`, вы можете быстро поднять необходимые сервисы с помощью подготовленного файла `docker-compose.yml`. Для запуска только PostgreSQL и Redis выполните:

```bash
# Установить Task через Go (если Go уже установлен):
go install github.com/go-task/task/v3/cmd/task@latest
task --version

task db-up
```

- Запустит контейнеры postgres и redis в фоновом режиме.
- Использует переменные окружения из вашего файла `.env` (например, `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`).

### Запуск миграций

```bash
# Применить все миграции
task mg:up
```

### Запуск бота

```bash
task a-run
```

## 4. Для Docker-запуска

> Если вы хотите запустить всё приложение целиком в Docker (PostgreSQL, Redis, migrator и сам бот), используйте готовый `docker-compose.yml`.

Файл `config/config.docker.yaml` уже содержит корректные значения для запуска в `Docker` (адреса сервисов postgres и redis). Секреты (`TELEGRAM_TOKEN`) задаются через переменные окружения в файле `.env` и автоматически подхватываются при запуске (благодаря `cleanenv.ReadEnv`). При необходимости вы можете переопределить любые другие параметры, добавив соответствующие переменные в `.env`.

### Запустите все сервисы

Выполните команду:

```bash
# Установить Task через Go (если Go уже установлен):
go install github.com/go-task/task/v3/cmd/task@latest
task --version

task up
```

Эта команда (определена в `Taskfile.yaml`) запустит все контейнеры в фоновом режиме:

- postgres — база данных;
- redis — хранилище сессий;
- migrator — однократно применит миграции (дождётся готовности PostgreSQL);
- app — сам бот.
  Все сервисы будут работать в фоновом режиме.

### Просмотр логов

Если необходимо убедиться, что бот запустился и авторизовался, посмотрите логи контейнера app:

```bash
# Логи контейнера app
docker compose logs -f app

# Логи контейнера migrator
docker compose logs -f migrator
```

### Остановка сервисов

```bash
task down
```

### Архитектура проекта

Проект следует принципам чистой архитектуры и разделён на слои:

- `cmd/` – точки входа:
  - `app` – основной бот
  - `migrator` – утилита для управления миграциями
- `internal/` – внутренний код приложения
  - `app/bootstrap` – инициализация компонентов (DI, создание зависимостей)
  - `clients/tg` – клиент для Telegram API
  - `commands/` – обработчики команд бота, сгруппированные по функциональности (например, `addtask`, `closed_task`, `completed_task`, `delete_task`, `set_timezone`, `viewstasks`)
  - `config` – загрузка и хранение конфигурации
  - `helpers/` – вспомогательные утилиты (работа с БД, Redis, сессиями, парсинг)
  - `interfaces/` – абстракции (контракты для хранилищ, сервисов, команд, отправителей сообщений)
  - `logger/` – обёртка над zap для логирования
  - `model/` – внутренние модели
    - `bottypes` – типы для inline-кнопок
    - `messages` – модель обработки входящих сообщений
  - `models/` – модели данных (User, Task, Status, NotificationType, Session и др.)
  - `repositories/` – работа с хранилищами: PostgreSQL (user, task, status, notification) и Redis (сессии)
  - `resources/` – текстовые константы (сообщения, названия кнопок, ошибки)
  - `services/` – бизнес-логика (DeadlineNotifier, OverdueChecker, SessionService)
  - `ui/buttons` – определения inline-кнопок для меню (сгруппированы по командам)

### Команды бота

После запуска отправьте боту команду `/start`, чтобы увидеть главное меню.

| Команда              | Описание                           |
| -------------------- | ---------------------------------- |
| `/start`             | Главное меню                       |
| `/tasks_action`      | Действия с задачами                |
| `/add_task`          | Добавить новую задачу              |
| `/view_tasks`        | Просмотреть задачи (с фильтрацией) |
| `/delete_task`       | Удалить задачу                     |
| `/completed_task`    | Отметить задачу как выполненную    |
| `/closed_task`       | Завершить задачу                   |
| `/settings_action`   | Настройки                          |
| `/set_timezone`      | Выбрать часовой пояс               |
| `/settings_view_all` | Просмотреть текущие настройки      |
